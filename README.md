A read-only Flipper Zero app that shows exactly what a reader puts on its
Wiegand lines: every bit, whatever the length, with hex, a format guess and
pulse timing. It is for the jobs where the access control software will not
show you the raw read.

It is a fork of the **Wiegand** app by Derek Jamison
(`jamisonderek/flipper-zero-tutorials`, `gpio/wiegand`, MIT licence).

## Wiring

| Reader wire | Flipper pin |
|---|---|
| D0 (green) | A4 (pin 4), through the divider below |
| D1 (white) | A7 (pin 2), through the divider below |
| Ground (black) | GND (pin 8, 11 or 18) |

Tap in parallel with the reader-to-panel run. Do not cut it. The panel keeps
working while you watch.

### Put a divider on each data line

Wiegand idles at 5 V and the Flipper is a 3.3 V device. Build this twice, once
for D0 and once for D1:

```
D0 or D1 ----[ 47k ]----+---- Flipper pin (A4 or A7)
                        |
                      [ 82k ]
                        |
                       GND
```

- A 5 V line arrives at the pin as about 3.2 V.
- It loads the line with 129k, which a panel pull-up will not notice.
- A slipped probe onto 12 V is limited to a fraction of a milliamp. That is
  damage limitation, not a guarantee.

This replaces the 10k/20k I suggested earlier. With a weak (10k) panel pull-up
the smaller values leave the Flipper's "high" level too close to its threshold.

Other rules:

- Never let reader power (red, usually 12 V) touch a Flipper pin.
- Run on battery. A USB cable to a laptop adds a second ground path.
- With the divider fitted, a disconnected lead reads `LO`. Without it, a
  disconnected lead floats and reads rubbish.

## Install

Copy `dist/wiegand_raw.fap` to the SD card at `apps/GPIO/` with qFlipper or the
mobile app. It appears under Apps, GPIO, **Wiegand Raw**.

**The supplied `dist/wiegand_raw.fap` is older than the source.** It was built
before the save, load and export fixes of 2026-11-22 and does not have them:
it still reports a failed save as saved. Rebuild with the steps below before
relying on it.

The supplied `dist/wiegand_raw.fap` is built for **Unleashed `unlshd-095`**. If
the Flipper says the app is out of date, rebuild it on a PC with Python
installed. This build needs firmware with API 88.26 or later in the 88 series:
it will not load on stock 1.5.1 (API 88.2) or on an older Unleashed release.

```bash
pip install ufbt
```

Point the build tool at the Unleashed SDK (once per machine):

```bash
ufbt update --index-url=https://up.unleashedflip.com/directory.json
```

Then build inside this folder:

```bash
ufbt
```

With the Flipper on USB, this builds, installs and starts it in one go:

```bash
ufbt launch
```

For stock firmware instead, run `ufbt update` with no arguments to switch back
to the official SDK, then `ufbt`. The source is the same either way.

## Using it

**Read.** Shows the idle state of both lines, then waits for one read.
`D0:HI D1:HI` is a healthy idle bus. `LO` means no pull-up, no reader power, a
short, or a lead that is not connected. After a read you get, scrolling down:

1. Bit count, with any warnings (`odd length`, `TRUNCATED`, `Glitches`).
2. The bits, in groups of four counted from the last bit, 16 per line.
3. Hex. Right-justified is what most access control software shows.
4. A format guess with parity, where the length matches a known format.
5. Pulse width and period, as min/avg/max and then per bit.

Left button saves the capture (`.wgn`). Right button, "To RFID", exports it to
the stock 125 kHz RFID app (see below). The button shows only when the length
maps to an RFID key type. Back returns to waiting for the next read.

A save that works shows `Saved <name>.wgn` under the bit count and the Save
button goes away. If the name is already on the card, or the file cannot be
written (no SD card, card full), the keyboard stays up and its heading says
`Name already used` or `Save failed: SD?`. Nothing is overwritten and the
capture is still in memory, so fix the name or the card and save again.

**Cable Test.** Badge one card about 20 times. The first read is the
reference; each later read is OK if it matches bit for bit, Bad if not. Green
flash for OK, red flash and a double buzz for Bad. Centre button resets. If the
first read was the bad one, every good read after it counts as Bad: reset and
start again.

To judge a cable run, take the Pulse range at the reader end and again at the
panel end, with the same leads and divider. Longer pulses at the panel end
mean the cable is slowing the edges. Compare the two ends with each other, not
with a datasheet number.

**Scan w/AutoSave.** Saves every read to its own file without asking. For
logging a stack of cards. `Saved` counts only the files that were really
written. A read that could not be written gives the error buzz and
`SAVE FAILED xN: SD card?` on screen: those reads are gone, so check the card
before carrying on.

**Load.** Opens a saved capture. Files saved by the original app use the same
`RAW_Data` layout and should load if you copy them into this app's folder.
The `TRUNCATED` and `Glitches` warnings saved with a capture come back with
it. `FILE DAMAGED? Says N bits` means the file's `Bits:` line does not match
the bits it holds: it was edited or cut short, so do not trust it.

### Export to the RFID app ("To RFID")

This hands a read to the stock 125 kHz RFID app so you can use its decoder and
analysis, instead of reinventing them here. It writes a standard `.rfid` key
file into `lfrfid/` on the SD card; open it from the RFID app's **Saved** list.
This is for analysis. It does not clone anything, and this app still never
drives a pin.

Only lengths that map to an RFID key type can be exported:

| Bits | Key type written | What the RFID app shows |
|---|---|---|
| 26 | `H10301` | Facility code and card number, parsed |
| 27–43 | `HIDProx` | "N-bit HID Proximity" and the hex; no field parse |
| everything else | not exported | the button is hidden |

Notes and limits:

- **26-bit is the one that gains field decoding.** For 27–43 bits the RFID app
  only shows length and hex, which this app already shows; the value there is
  getting the read into the `.rfid` ecosystem.
- **A 26-bit export can look better than the read was.** `H10301` stores only
  the facility code and card number, and the RFID app works the parity out
  again. A misread with wrong parity therefore exports as a clean card. The
  app warns when it does this (`WARNING: bad parity not kept`) and when the
  read had glitches (`WARNING: read had glitches`). Treat such a file as
  suspect.
- **48-bit and longer cannot be exported.** The Flipper's generic HID key holds
  44 data bits, so 48-bit Corporate 1000 and anything longer has no correct
  target. Use the `.wgn` save and the hex instead.
- **4, 8 and 24-bit are not exported** (no matching key type).
- The byte layouts were taken from the Unleashed firmware and the 27–43-bit
  length prefix is checked in the test suite against a copy of the firmware's
  own length decoder. Still, **confirm one real card end to end on the bench**
  (step 11 below) before relying on it.
- Exported files are working credentials, the same as `.wgn` files. Delete them
  when the job is done.

### The format guess is only a guess

It is chosen by bit count alone. Two different formats of the same length look
identical to it. The bits are the truth; the decode is a hint.

| Bits | Decoded as | Parity checked |
|---|---|---|
| 4, 8 | Keypad key | 8-bit complement check |
| 24 | 8-bit facility code, 16-bit card number | none in this format |
| 26 | HID H10301 | yes |
| 34 | HID H10306 | yes |
| 35 | HID Corporate 1000 | yes, all three |
| 36 | Keyscan C15001 | yes |
| 37 | HID H10304, and the same bits as H10302 | yes |
| 48 | HID Corporate 1000 | yes, all three |
| anything else | not decoded | no |

Field positions and parity rules were checked against the Proxmark3 client
source. The sample capture in `examples/`, a real 48-bit Corporate 1000 read,
passes all three parity checks.

### What "Glitches" means

A rising edge with no falling edge before it: a spike too short for the
Flipper to catch the line low. A few on a noisy run are a clue. It is a count
of what the Flipper happened to notice, not a noise measurement.

## Saved files

Captures go to `apps_data/wiegand_raw/` on the SD card as `.wgn` text files.
RFID exports go to `lfrfid/` as `.rfid` files (see the export section above).
Both are working credentials; delete them when the job is done.

`.wgn` layout:

```
Filetype: Flipper Wiegand Key File
Version: 1
Protocol: RAW
Bits: 26
Truncated_Bits: 0
Glitches: 0
RAW_Data: D0 0 2560 D0 128000 130560 ...
PACS_Binary: 00000010110100010110100011
Hex_Right_Justified: 00B45A3
Hex_Left_Justified: 02D168C
```

`RAW_Data` is each bit's fall and rise time in 1/64 microsecond ticks from the
first edge. A file is either written whole or not left on the card: one that
could not be finished is removed.

**These files are working credentials.** Delete them when the job is done.

## Limits

- Not a scope. It reports bit count, bits and edge timing. It cannot see
  voltage levels, ringing or ground offset.
- A read whose length is wrong but whose bits happen to be valid for another
  format will be decoded as that other format.
- Pulse timing includes a few microseconds of interrupt jitter.
- A frame ends after 25 ms of silence. Readers that pause longer than that
  mid-frame would be split in two.
- If the reader is set to OSDP, those wires carry RS-485 and this shows
  nothing useful.

## Bench check before first use

On a bench, with a reader you know is good and a card you know the number of:

1. Open **Read** with nothing connected: expect `D0:LO D1:LO` (with dividers).
2. Connect to a powered reader and panel: expect `D0:HI D1:HI`.
3. Badge the known card: bit count, facility code and card number are right,
   and parity is OK.
4. Scroll the result: text is readable and nothing is cut off at the edges.
5. Save it, then **Load** it: same bits. Save again under the same name: the
   keyboard must refuse with `Name already used`.
6. Pull the SD card and read the `.wgn` file on a PC: lines as shown above.
7. **Cable Test** with 20 badges: 20 OK, 0 Bad, pulse range a few
   microseconds wide.
8. Badge a second, different card in Cable Test: it counts as Bad.
9. Check the door still works normally with the Flipper attached.
10. Pull the SD card, open **Scan w/AutoSave** and badge once: error buzz,
    `SAVE FAILED x1`, and `Saved 0`. Put the card back.
11. With a 26-bit card: on the result screen press **To RFID**, then open the
    stock RFID app and load the file from `lfrfid/`. The facility code and card
    number must match the Wiegand read. (This is the one export step worth
    verifying; the longer formats only carry length and hex.)

## Tests

```bash
python3 test/run_tests.py
```

Needs `gcc`. It checks formatting and decoding against values worked out
separately in Python, runs the capture logic against simulated edges, checks
the RFID export, feeding each generated `HIDProx` buffer back through a copy
of the firmware's own HID length decoder, and checks the capture file text by
saving to and loading from memory. The storage calls themselves, the name
check and the screens are not covered: those need a Flipper. Nothing in
`test/` is built into the app.
